# How to publish serverpod_argon2

To publish this package, create a new tag and push it to the repository. The
[publish workflow](.github/workflows/publish.yaml) builds the prebuilt
libraries, tests them, and publishes the package to pub.dev.

The tag needs to be in the format `vX.Y.Z`, where `X`, `Y`, and `Z` are
integers. The version number should be incremented according to the
[Semantic Versioning](https://semver.org/) rules.

It is also possible to publish a pre-release version by adding a suffix to the
version number. For example, `v1.0.0-dev.1` is a pre-release version of
`v1.0.0`.

## Prepare the release

Before publishing a new version, follow these steps to prepare the release:

1. Update the version number in `pubspec.yaml`. pub.dev rejects the upload if
   it does not match the tag.
2. Update `CHANGELOG.md` with the changes in the new version. This is the
   changelog that is displayed on pub.dev.
3. If `src/argon2.zig`, `build.zig` or the zig version changed, run
   `dart run tool/build_binaries.dart` and commit the regenerated
   `lib/src/module/argon2_wasm.g.dart`. The workflow fails if the committed
   file is stale.
4. Merge the changes to the `main` branch and then create a tag based on that
   commit.

## Create a new tag

The preferred way to create a new tag is to use GitHub's interface to create a
new release.

GitHub will suggest the latest commit on the `main` branch as the target for
the tag. Make sure to select the correct commit.

An automatically generated changelog will be created for the release. This
changelog is not used by pub.dev. Instead, the `CHANGELOG.md` file is our
source of truth. Therefore, the changelog generated by GitHub can be left as
is.

## What the workflow does

1. Builds every native target into `binary/` on macOS (the iOS targets need
   Xcode) and checks the committed wasm module is current.
2. Runs the tests against the prebuilt libraries on Linux, macOS and Windows,
   with the zig build files removed so nothing can build from source.
3. Publishes with `binary/` included. `binary/` is never committed.

## One-time setup

Automated publishing must be enabled on the package's pub.dev admin page, with
repository `serverpod/serverpod_argon2` and tag pattern `v{{version}}`. The
first version has to be uploaded manually: run
`dart run tool/build_binaries.dart` on a Mac, then `dart pub publish`.
